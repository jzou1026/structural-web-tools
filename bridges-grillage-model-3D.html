Theory & Documentation

Engineering mechanics, program architecture, and formal references for Bridge Grillage Studio.

Development analysis tool. The equations below document the implemented formulation, but the software and all results still require independent verification by a qualified bridge engineer.

Part I — Engineering Theory

v1.7 update — CSA S6:25 Clause 3.8 compliance

ULS traffic load = max(CL-W truck, CL-W lane load). Per Clause 3.8.3.1.1 and 3.8.4.1(d)(i), normal-traffic ULS/SLS-1 load is the CL-W truck or the CL-W lane load, whichever governs — not both combined. Every ULS sweep now runs both patterns and envelopes them at every station: (1) the full 5-axle truck with dynamic load allowance (DLA) and the Table 3.6 multi-lane factor \(R_L\); and (2) the CL-W lane load — each axle at 80% (Clause 3.8.3.1.3) plus a 9 kN/m UDL per design lane, with no DLA on either component (Clause 3.8.4.5.1 excludes the lane load, including its axle portion, from dynamic amplification).

DLA = 0.25 is used for the whole-truck case because this tool evaluates global girder actions using all 5 axles simultaneously, which falls under Clause 3.8.4.5.3(d) ("0.25 where three axles... or more than three axles... are used"). Clauses 3.8.4.5.3(a)-(c) (0.50/0.40/0.30 for single- or paired-axle local checks) apply to deck-joint or local-component design, which is outside this tool's scope (global main-girder grillage analysis).

FLS uses a single CL-W truck (DLA applied, no lane load, no multi-presence factor) centred in one physical travel lane at a time, per Clause 3.8.4.1(c).

Known simplifications / out of scope: (i) Clause 3.8.4.1(a)-(b) permit dropping individual truck axles or partial-length UDL where doing so increases the tracked response (an influence-line-based refinement); this tool instead sweeps the full vehicle as a rigid unit and applies the lane UDL over the full length, which is a reasonable but slightly conservative-or-unconservative simplification depending on span continuity — verify governing envelopes for continuous spans against an influence-surface analysis before final design. (ii) Braking force (3.8.6), lateral curb load (3.8.7), and barrier loads (3.8.8) are horizontal/local actions not captured by this vertical-only grillage idealization (see Clause 3.8.4 note below). (iii) Pedestrian, maintenance-vehicle, and special-truck loads (3.8.9-3.8.12) are not modelled; this bridge has no sidewalks in its default configuration.

1. Scope and structural idealization

The bridge deck is idealized as an orthogonal grillage located in the global \(X\)-\(Y\) plane. Global \(X\) is longitudinal, global \(Y\) is transverse, and global \(Z\) is upward. Main girders are longitudinal line elements, while transverse slab strips distribute wheel loads between girders. The current solver is linear elastic, first order, and small displacement.

Each grillage node has the reduced displacement vector shown in Equation 1.

\[\mathbf d_i=\begin{bmatrix}w_i&\theta_{x,i}&\theta_{y,i}\end{bmatrix}^{\mathsf T}\tag{1}\]Equation 1
  • \(w_i\) is vertical displacement at node \(i\).
  • \(\theta_{x,i}\) is rotation about global \(X\).
  • \(\theta_{y,i}\) is rotation about global \(Y\).

2. Bridge geometry and longitudinal discretization

Total deck width is calculated using Equation 2.

\[B_{\mathrm{deck}}=W_{\mathrm{clear}}+2b_{\mathrm{curb}}\tag{2}\]Equation 2
  • \(B_{\mathrm{deck}}\) is total deck width.
  • \(W_{\mathrm{clear}}\) is clear roadway width.
  • \(b_{\mathrm{curb}}\) is the curb width on each edge.

For equally spaced girders and equal exterior overhangs, Equation 3 determines the first girder line, and Equation 4 determines every girder coordinate.

\[e_o=\frac{B_{\mathrm{deck}}-(n_g-1)S_g}{2}\tag{3}\]\[y_{G,i}=e_o+(i-1)S_g\tag{4}\]Equations 3 and 4
  • \(e_o\) is equal exterior overhang.
  • \(n_g\) is the number of main girders.
  • \(S_g\) is girder spacing.
  • \(y_{G,i}\) is the transverse coordinate of girder \(i\).

Each user-defined span is divided using Equation 5. The larger of the requested envelope divisions and the strict maximum-mesh requirement governs.

\[n_i=\max\!\left(n_{\mathrm{env}},\left\lceil\frac{L_i}{\Delta x_{\max}}\right\rceil\right),\qquad \Delta x_i=\frac{L_i}{n_i}\tag{5}\]Equation 5
  • \(n_i\) is the number of intervals in span \(i\).
  • \(n_{\mathrm{env}}\) is the user-selected divisions per span, default 10.
  • \(L_i\) is span length.
  • \(\Delta x_{\max}\) is the maximum permitted longitudinal element length.
  • \(\Delta x_i\) is the generated interval length.

3. Material and strip properties

Concrete shear modulus is calculated using Equation 6. Equations 7 and 8 define transverse strip bending and torsional properties for tributary width \(b_t\) and slab thickness \(t_c\).

\[G_c=\frac{E_c}{2(1+\nu_c)}\tag{6}\]\[I_{\mathrm{strip}}=\frac{b_t t_c^3}{12}\tag{7}\]\[J_{\mathrm{strip}}=\frac{b_t t_c^3}{3}\tag{8}\]Equations 6 to 8
  • \(E_c\) is concrete Young's modulus.
  • \(G_c\) is concrete shear modulus.
  • \(\nu_c\) is concrete Poisson ratio.
  • \(I_{\mathrm{strip}}\) is transverse-strip vertical bending inertia.
  • \(J_{\mathrm{strip}}\) is the rectangular-strip torsional constant used by this model.

4. Element stiffness

Longitudinal bending uses the local order \([w_i,\theta_{y,i},w_j,\theta_{y,j}]\). Transverse bending uses \([w_i,\theta_{x,i},w_j,\theta_{x,j}]\). The Euler–Bernoulli bending matrix is Equation 9.

\[\mathbf k_b=\frac{EI}{L^3}\begin{bmatrix}12&6L&-12&6L\\6L&4L^2&-6L&2L^2\\-12&-6L&12&-6L\\6L&2L^2&-6L&4L^2\end{bmatrix}\tag{9}\]Equation 9
  • \(E\) is Young's modulus for the member.
  • \(I\) is the vertical bending inertia.
  • \(L\) is member length.

St. Venant torsion is represented by Equation 10.

\[\mathbf k_t=\frac{GJ}{L}\begin{bmatrix}1&-1\\-1&1\end{bmatrix}\tag{10}\]Equation 10
  • \(G\) is shear modulus.
  • \(J\) is the assigned torsional constant.

5. Supports, assembly, and solution

Vertical displacement is restrained at every main-girder intersection with an abutment or pier line. Rotations remain free, so continuous girder action can develop over interior supports. Element matrices are assembled according to Equation 11, and the free system is solved using Equation 12.

\[\mathbf K=\sum_e \mathbf A_e^{\mathsf T}\mathbf k_e\mathbf A_e\tag{11}\]\[\mathbf K_{ff}\mathbf d_f=\mathbf F_f\tag{12}\]Equations 11 and 12
  • \(\mathbf K\) is the assembled global stiffness matrix.
  • \(\mathbf A_e\) is the Boolean element-to-global location matrix.
  • \(\mathbf k_e\) is an element stiffness matrix.
  • \(\mathbf K_{ff}\), \(\mathbf d_f\), and \(\mathbf F_f\) are the free-free stiffness matrix, free displacement vector, and free load vector.

The symmetric positive-definite matrix is Cholesky-factorized once using Equation 13 and reused for every vehicle position.

\[\mathbf K_{ff}=\mathbf L\mathbf L^{\mathsf T}\tag{13}\]Equation 13
  • \(\mathbf L\) is the lower-triangular Cholesky factor.

6. Axles, ULS paths, and FLS paths

Each axle input is the total transverse axle load. The two wheel-line forces are calculated using Equation 14.

\[P_{\mathrm{wheel}}=\frac{P_{\mathrm{axle}}}{2}\tag{14}\]Equation 14
  • \(P_{\mathrm{axle}}\) is total load on one transverse axle.
  • \(P_{\mathrm{wheel}}\) is load on one of the two transverse wheel lines.

ULS wheel force is factored using Equation 15.

\[P_{\mathrm{ULS}}=\frac{P_{\mathrm{axle}}}{2}(1+\mathrm{DLA})R_L\gamma_{\mathrm{ULS}}\tag{15}\]Equation 15
  • \(\mathrm{DLA}\) is dynamic load allowance.
  • \(R_L\) is the multiple-presence factor.
  • \(\gamma_{\mathrm{ULS}}\) is the user-entered ULS live-load factor.

FLS places one truck at a time in each physical travel lane. Lane and wheel coordinates are calculated using Equation 16.

\[y_{\mathrm{lane},i}=b_{\mathrm{curb}}+S_{\mathrm{left}}+\left(i-\frac12\right)W_{\mathrm{lane}},\qquad y_{\mathrm{wheel}}=y_{\mathrm{lane},i}\pm\frac{S_w}{2}\tag{16}\]Equation 16
  • \(S_{\mathrm{left}}\) is left shoulder width.
  • \(W_{\mathrm{lane}}\) is physical travel-lane width.
  • \(S_w\) is transverse wheel-line spacing.

7. Wheel-load interpolation

A wheel between neighboring X stations and girder lines is distributed to four surrounding vertical DOFs using Equations 17 and 18.

\[\alpha=\frac{x-x_i}{x_{i+1}-x_i},\qquad \beta=\frac{y-y_j}{y_{j+1}-y_j}\tag{17}\]\[\begin{aligned}P_{i,j}&=(1-\alpha)(1-\beta)P, & P_{i+1,j}&=\alpha(1-\beta)P,\\P_{i,j+1}&=(1-\alpha)\beta P, & P_{i+1,j+1}&=\alpha\beta P.\end{aligned}\tag{18}\]Equations 17 and 18
  • \(x,y\) are wheel coordinates.
  • \(x_i,x_{i+1}\) are adjacent longitudinal stations.
  • \(y_j,y_{j+1}\) are adjacent girder coordinates.
  • \(\alpha,\beta\) are interpolation fractions.
  • \(P\) is the factored wheel load.

8. Moving-load stepping and response recovery

The leading axle moves from the left bridge edge until the trailing axle reaches the right bridge edge. Equation 19 defines total travel distance.

\[L_{\mathrm{travel}}=L_{\mathrm{bridge}}+L_{\mathrm{vehicle}}\tag{19}\]Equation 19
  • \(L_{\mathrm{bridge}}\) is the sum of all span lengths.
  • \(L_{\mathrm{vehicle}}\) is the largest cumulative axle offset.

Longitudinal element end actions are recovered by Equation 20. The vector contains near-end shear and moment followed by far-end shear and moment under the program's local sign convention.

\[\mathbf q_e=\mathbf k_e\mathbf d_e=\begin{bmatrix}V_i&M_i&V_j&M_j\end{bmatrix}^{\mathsf T}\tag{20}\]Equation 20
  • \(\mathbf q_e\) is the local member-end action vector.
  • \(\mathbf d_e\) is the local element displacement vector.
  • \(V_i,V_j\) are end shears and \(M_i,M_j\) are end moments.

ULS and FLS envelopes are accumulated using Equation 21.

\[M_{\max}(x)=\max_p M(x,p),\quad M_{\min}(x)=\min_p M(x,p),\quad V_{\max}(x)=\max_p V(x,p),\quad V_{\min}(x)=\min_p V(x,p)\tag{21}\]Equation 21
  • \(p\) identifies a vehicle position and, for FLS, a physical lane case.
  • \(M_{\max},M_{\min}\) are bending-moment envelopes.
  • \(V_{\max},V_{\min}\) are shear-force envelopes.

9. Support reaction recovery and correlated envelopes

After each load-position solve, restrained vertical reactions are recovered from the full global equilibrium equation in Equation 22. Reactions at all girder bearings on one support line are summed into one support-line reaction.

\[\mathbf R=\mathbf K\mathbf D-\mathbf F\tag{22}\]Equation 22
  • \(\mathbf R\) is the global residual-force vector; restrained vertical entries are support reactions.
  • \(\mathbf K\) is the full assembled stiffness matrix.
  • \(\mathbf D\) is the complete displacement vector including zeros at restrained DOFs.
  • \(\mathbf F\) is the complete applied-load vector.

For each target support, the software records the vehicle position at which that support reaches its maximum or minimum. The complete support-reaction vector from the same position is stored. Therefore, every reaction shown across a Max or Min row is concurrent and statically compatible with the governing target-support reaction; the other columns are not independent envelope maxima.

10. Results interpretation

The ULS and FLS result pages plot Equation 21 at the generated bridge stations. BMD units are kN·m; SFD units are kN. Shaded areas are graphical fills between the numerical envelope and the zero axis, not integrated quantities. The CSV downloads contain the same station-by-station ordinates. The values currently represent member-end results at generated stations; exact interior extrema beneath axles are not independently searched.

Part II — Coding Theory

v1.7 update — solver engine

The stiffness assembly now reuses the general 3D space-frame beam element (localStiffness3D, memberAxes, transform3D) from the companion Space Frames v1.0 tool verbatim, rather than a hand-written 2-DOF grillage beam stiffness. Every grillage member is horizontal, so each element's local-z axis is always global Z; this makes the 12-DOF element's {u,v,rz} ("in-plane") and {w,rx,ry} ("out-of-plane") sub-blocks exactly decoupled. Restraining U1, U2, and R3 (in the space-frame element's local numbering: axial translation, in-plane shear translation, and in-plane bending rotation) at every node — and leaving only U3, R1, R2 (vertical translation, torsion, out-of-plane bending rotation) free — therefore reproduces a dedicated 3-DOF-per-node grillage exactly, while genuinely reusing the same element formulation as the general-purpose 3D solver. An LU-factor-once/reuse layer (luFactor/luSolve) sits on top purely so a several-hundred-position moving-load sweep does not re-run elimination on every step — the stiffness matrix itself is built once per model, then re-solved for each truck position's load vector.

Wheel-load application: each axle's load is distributed by bilinear interpolation onto the four grid nodes surrounding its (x, y) position — the standard finite-element consistent nodal-load approach for a point load that does not land exactly on a node — rather than inserting extra "dummy" longitudinal frame elements along every possible wheel path. Adding real elements at every ULS/FLS wheel line (there can be a dozen or more distinct transverse positions once every design lane's wheel lines are enumerated) would multiply the transverse node count several-fold for no stiffness benefit, and made the earlier dense-matrix formulation impractically slow (multi-minute factorizations) for a sweep of hundreds of truck positions. Bilinear nodal distribution gives the same load path into the grillage without that cost, and for wheels outside the outermost girder line the same formula linearly extrapolates — representing the overhang's lever-arm effect — rather than requiring separate cantilever/edge members.

1. Application architecture

The application is a single HTML document containing CSS, inline SVG generation, and plain JavaScript. The only external runtime resource is MathJax, loaded from a CDN for live LaTeX rendering. Model state is held in DOM inputs, the dynamic \(\texttt{SPAN\_DATA}\) array, and the current result object.

2. Input-to-output pipeline

  1. Input handlers update geometry, path, factor, mesh, and axle settings.
  2. The span array generates cumulative support stations and longitudinal X stations using Equation 5.
  3. Geometry routines create node indices, longitudinal girder members, and transverse slab-strip members.
  4. Local bending and torsion blocks from Equations 9 and 10 are assembled into the global matrix using Equation 11.
  5. Support restraints define free DOFs and the free matrix is Cholesky-factorized using Equation 13.
  6. Each ULS or FLS vehicle position creates a new load vector using Equations 14 to 18.
  7. Forward and backward substitution solve Equation 12 without refactorizing the stiffness matrix.
  8. Element actions are recovered using Equation 20, the four member-force envelopes in Equation 21 are updated, and full support reactions are recovered using Equation 22.
  9. SVG polylines and polygons render BMD and SFD envelopes; CSV routines export the same arrays.

3. Dynamic diagrams and saved working files

Bridge geometry, ULS design lanes, and FLS travel lanes are redrawn as inline SVG whenever an input or page changes. The Download Working File feature clones the current document, writes current input values and selected options into the clone, replaces the embedded span array, and downloads a time-stamped standalone HTML file.

4. MathJax and print flow

LaTeX equations are delimited by \(\backslash(\,\backslash)\) for inline math and \(\backslash[\,\backslash]\) for display math. Before the browser print dialog opens, the print routine waits for \(\texttt{MathJax.typesetPromise()}\) to complete and then applies a short delay. Print CSS prevents equation containers from splitting across pages.

5. Numerical safeguards

The application verifies matrix stability through Cholesky factorization, sanitizes nonfinite chart ordinates, preserves a strict maximum longitudinal mesh length, and invalidates displayed results when geometry changes. These checks catch implementation failures but do not replace independent structural verification.
