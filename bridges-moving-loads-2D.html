How This Program Works

This page explains the calculation workflow in plain language. The program takes the bridge layout and user-defined axle group, moves the axle group across the bridge in small increments, solves the beam at each position, then keeps the governing shear, moment, and reaction values as envelopes.

Overall workflow:
1. Read truck, bridge, support, and step-size inputs
2. Generate every truck position from start to finish
3. Convert axles currently on the bridge into span point loads
4. Solve the beam using the direct stiffness method
5. Extract V(x), M(x), and support reactions
6. Update max/min envelopes at each output station
1. Inputs the Program Uses

The analysis intentionally uses only the inputs needed for a moving point-load beam analysis. The truck table defines the axle numbers, axle offsets, and axle loads. The bridge table defines span length, uniform load, station divisions, relative stiffness, and support conditions.

Truck input:
Xᵢ = axle offset measured from Axle 1
Wᵢ = downward axle load

Bridge input:
L = span length
q = uniform span load, if required
div = number of reporting divisions
Relative EI = flexural stiffness ratio used by the stiffness solver

For the PDF defaults, Axle 1 has X = 0.0, Axle 2 has X = 4.3, Axle 3 has X = 8.5, and Axle 4 has X = 12.8. Because Axle 4 has the largest offset, it is the last axle in the vehicle group as the truck moves across the beam.

2. Vehicle Positioning

The program uses a moving reference position, p. At each iteration, every axle global coordinate is calculated from p and that axle's offset. This is what lets the full vehicle move across the bridge as one rigid axle group.

Axle global coordinate:
xᵢ = p − Xᵢ

Start condition:
p_start = X₁
Therefore x₁ = X₁ − X₁ = 0

End condition:
p_end = L_bridge + X_last
Therefore x_last = L_bridge

This enforces the requested boundary conditions: iteration 1 starts with Axle 1 at the very left of the beam, and the last iteration ends with Axle 4 at the very right of the beam for the default 4-axle truck.

3. What Happens at Each Iteration

At a given vehicle position, not every axle necessarily sits on the bridge. Some axles may still be approaching the bridge, while others may have already left. The program checks each axle coordinate and only applies that axle if it lies within the bridge limits.

Axle is active when:
0 ≤ xᵢ ≤ L_bridge

If active:
assign Wᵢ as a point load on the span containing xᵢ

If inactive:
ignore the axle for that iteration

For multi-span bridges, the program finds which span contains each active axle and converts its global coordinate into a local span distance measured from that span's left node.

4. Beam Solver

Once the active axle loads are known, the bridge is solved as a beam model. Each node has a vertical displacement degree of freedom and a rotational degree of freedom. Supports restrain the relevant degrees of freedom, and the remaining unknown displacements are solved from the stiffness equations.

Beam element degrees of freedom:
[v₁, θ₁, v₂, θ₂]

Partitioned stiffness equation:
K_ff D_f = F_f − K_fc D_c

After D is known:
member end forces, reactions, V(x), and M(x) are recovered

Point loads are converted into equivalent nodal load terms using standard beam shape-function relationships, so the solver can handle a point load located anywhere along a span, not just at nodes.

5. Output Stations and Envelopes

The program does not only report results at supports. It creates output stations along each span using the division input. At every station, it samples shear and moment for every truck position and keeps the maximum and minimum values.

At each station x:
Vmax(x) = maximum V(x,p) over all p
Vmin(x) = minimum V(x,p) over all p
Mmax(x) = maximum M(x,p) over all p
Mmin(x) = minimum M(x,p) over all p

This is why the results page has envelope curves instead of just one shear or moment diagram. The plotted curve represents the governing values from many separate beam analyses.

6. Reaction Envelopes

Support reactions are also tracked at every vehicle position. For each support, the program stores the largest and smallest vertical reaction that occurred during the truck crossing.

At each support j:
Rmax(j) = maximum R(j,p) over all p
Rmin(j) = minimum R(j,p) over all p

These reaction envelopes are useful when checking bearings, supports, or substructure demand caused by moving loads.

Built-In CSA S6:25 Traffic Load Cases

The Inputs page includes two preset buttons for normal traffic loading: CSA S6:25 CL-625 Truck and CSA S6:25 CL-625 Lane Load. The CL-625 truck uses the five-axle CL-W truck pattern with W = 625 kN. The lane-load preset applies 80% of the CL-625 truck axles together with a 9 kN/m uniform lane load.

CL-625 Truck preset:
Axle offsets X = 0, 3.6, 4.8, 11.4, 18.0 m
Axle loads W = 50, 125, 125, 175, 150 kN

CL-625 Lane preset:
Axle loads = 0.80 × truck axles = 40, 100, 100, 140, 120 kN
Uniform load q = 9 kN/m on each span
Important Assumptions and Practical Notes

Consistent units are required. The program does not convert between unit systems. If forces are entered in kN and distances in m, then moments are reported as kN·m. If forces and distances use another consistent system, results follow that system.


The nudge distance controls resolution. A smaller step gives a smoother and potentially more accurate envelope, but it also increases the number of beam analyses. A larger step runs faster but may miss a narrow peak response.


The program is an engineering aid, not a substitute for checking. Review the input units, support conditions, span layout, step size, and governing cases before using results for design decisions.
